# 0006 — One simple MVP for family introductions and younger self-use

- Date: 2026-09-13
- Status: Partially superseded by [0007](0007-v1-alarms-and-focus.md): alarms restored and focus modes required. Two audience paths, agency and simple tone remain. Historical rationale below; implementation pending.

## Context

The founder requested a clear pitch/usability MVP, a Claude task, and tone inspired by Straight-Line Leadership. A correction explicitly retains younger self-directed users alongside concerned children introducing their parents. Lord Shani is intended as a spiritual connection for receptive parents; focus and metacognition motivate younger users.

## Options

Retaining every existing feature would leave a complex initial offering. A parent-only blocker would drop the corrected younger audience. Separate family and productivity applications would duplicate the first experiment. One shared core with different voluntary presentation supports both without creating two products.

## Decision

Use one intention, one distracting app, an immediate timed focus session, optional local pause and brief review. Both entry paths use the same participant-owned controls. Spiritual presentation is optional. Define plain, actionable wording in a reusable guide. Retain existing adult-first testing while recording school-age use as a future track.

Defer alarms, charts, scroller, large library, recurring scheduling, payment and family dashboards from launch visibility. Preserve implementation and safe management of previously active services. Claude receives an end-to-end scoped implementation task, including UI; task preparation is not implementation completion.

## Consequences

PM refinement on the same date: prioritize family acquisition learning after a shared shakedown, retain young self-use, and reuse the local pause as an optional pre-account preview explicitly without blocking. Add editable activity presets and helper handback, expose voluntary Shani framing where an invitation can be understood, and require complete Hindi before Hindi-speaking parent tests. Collect separate manual funnels. Defer auth architecture and reminders until observed friction justifies them. See the [PM review](../../ai_org/product_manager_mvp_review_2026-09-13.md).

The first build tests a smaller promise and cannot advertise the full spiritual/AI experience. Immediate starts require voluntary repetition. Both audience paths need separate qualitative feedback. Optional faith framing must be tested with actual parents. The team incurs routing/upgrade work to hide existing capabilities safely.

## Revisit when

Participants repeatedly use the core and identify a specific missing capability, or one entry path fails to show useful repeated action. Reintroduce features through the [backlog](../strategy/shanivar-launch-backlog.md) with evidence and acceptance criteria. Do not broaden scope because code already exists.
