# Shanivar staged launch backlog

Current scope: [initial MVP](../../android-app/INITIAL_MVP_SCOPE_2026-09-13.md). This is a sequencing decision, not a schedule or a claim that deferred features are missing. Preserve existing implementations and reverify them when reintroducing them.

| Stage | Item | Why later / return gate |
| --- | --- | --- |
| Initial | Immediate focus modes, editable goal presets, selected app set, brief pause, optional review | Establish useful behavior for parents and younger users |
| Initial | Plain and optional Shani-inspired wording; verified English/Hindi core | Two motivations, one experience; each language needs comprehension QA |
| Initial | Optional pre-account local pause, editable activity presets, helper handback guide | Reuse the core exercise and static copy to reduce first-use friction; preview never claims blocking |
| Initial | Discoverable optional Shani explanation and manual pilot worksheet | Test voluntary parent interest separately from helper interest and young-adult usage |
| Next, conditional | Lightweight reminder experiment | Participants value sessions but forget to initiate; test before building a repeat scheduler |
| Later, conditional | OTP/passwordless auth or local-first protected sessions | Actual account/network barriers prevent use; do not rewrite identity or enforcement on speculation |
| Next | Automatic focus schedules and multiple windows | Users repeat the manual loop and identify timing friction; add reliable schedule semantics |
| Next | Fewer prompts and independence follow-up | Establish repeated benefit before measuring transfer without support |
| Next | Extra Indian languages or audio | Actual participant language/accessibility need and full delivery quality |
| Initial | One editable alarm, repeat days, movement/non-walking dismissal, test sound and real readiness | Founder-required v1; verify recurrence, stop guarantees and physical-device behavior |
| Later | Multiple alarms, camera/QR missions, sleep tracking and wake-up rechecks | Demand beyond one reliable alarm; preserve a small first launch |
| Later | Astrology and birth inputs | Voluntary demand; calculation provenance and incremental usefulness checks |
| Later | AI reflection/scroller and longitudinal memory | Fixed review is insufficient; show useful action without creating another consumption loop |
| Later | Larger practice library and personalized routing | Repeated need for more variety; source and suitability review |
| Later | WhatsApp and remote invitation links | Channel demand, reliable destination and consent; no unrequested outreach |
| Later | Payments or sponsored access | Experienced value and a specific tested offer; no inferred release fees |
| Readiness gate | School-age availability within all-ages direction | Complete age-appropriate account/consent/privacy and comprehension scope before claiming all-age readiness; adult testing first |
| Hold | Family accounts/reporting | Only a concrete mutually chosen need; no private activity or journal sharing by default |
| Hold | XP, consciousness stages, ranks and gamified feed | Evidence of benefit consistent with user agency; no spiritual or intelligence scoring |
| Hold | Apparel integration and large content campaigns in app | No contribution to testing the first core loop |

Reintroduce one capability at a time. Record the user problem, evidence, tradeoff, owner, test and stop condition in the release log before promoting a backlog item into launch scope. Existing code is not justification by itself.

The founder's [v1 decision](../decisions/0007-v1-alarms-and-focus.md) restores alarms and focus modes. The earlier [PM review](../../ai_org/product_manager_mvp_review_2026-09-13.md) sequences family acquisition learning first after the two-path shakedown. It does not remove young self-use or establish parent demand. Whole-app versus feed-only needs and voluntary session initiation are unresolved fit questions.
