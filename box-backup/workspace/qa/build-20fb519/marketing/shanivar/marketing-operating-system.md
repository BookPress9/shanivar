The manager has delegated **internal editorial approval** for routine, stance-consistent posts: wording, hooks, format, sequencing and asset QA. Routine creative does not return to the founder for approval by default. This authority does not accept proposed doctrine, bypass product release gates, provide missing account credentials, or create external-action authorization beyond the user's actual instructions. Reuse any existing publishing authorization within its scope; do not request it repeatedly. A materially new doctrinal commitment goes to the founder with the exact proposed wording and evidence, while other work continues.

## Weekly production contract

Target **three feed posts per week: two AI UGC-style Reels and one carousel** once video generation/rendering access produces usable final videos. Suggested spacing is Monday/Wednesday/Friday, initially 19:30 Asia/Kolkata; convert from that timezone for each date. This is a planning convention, not an account-proven optimum.

AI UGC means illustrative creator-style scenes, not actual customer testimony. Use original fictional presenters/scenes and honest synthetic-media disclosure suitable for the platform. Never invent “I used Shanivar and it cured/changed me” accounts, reviews, customers, metrics or endorsements. Do not clone identifiable people or voices without permission. Verify rights to music, voice and reference assets; captions must match the final audio. Keep actors and product UI separate from proof of product availability. Production authorization does not authorize paid subscriptions, new paid tools, ads or spending.

**Fallback now:** the [current execution package](execution-2026-09-30/README.md) contains three rendered four-slide English carousels, IDs `SHN-20260930-STEADY-EN`, `SHN-20261002-LAMP-EN`, `SHN-20261005-CUPS-EN`. Manager reviews them against the stance intake, then feeds them into the next available slots. Do not delay the entire account for video access or call these carousels UGC videos. Retain their IDs if dates move; record actual dates separately. Supersede conflicting unposted legacy slots rather than running both queues.

Maintain a **rolling seven-day ready buffer**: three complete, internally approved, accessible upload packages beyond posts already published. Each has final media, caption, alt text/subtitles, destination, rights/disclosure check, stance intake reference and approval revision. Drafts and unrendered video scripts do not count. A below-target buffer is visible, with an owner and recovery deadline.

Deadlines use the next publication slot as T:

| Deadline | Deliverable | If missed |
| --- | --- | --- |
| T−72h | Manager brief and delegated assignments accepted. | Narrow the brief to source-supported material; keep the slot using existing approved buffer. |
| T−48h | Exact scripts/copy and first media render. | Manager assigns an available producer/tool or selects a completed carousel; do not buy tools implicitly. |
| T−24h | Final render, QA, internal approval and account-route readiness. | Escalate specific account dependency immediately; mark slot At risk and assign fallback owner. |
| T | Publish exact approved package once; verify response. | Record Failed/Unverified with cause. Reconcile uncertain result before retrying; prevent duplicate posts. |
| T+24h and T+7d | Record available raw Insights and actual snapshot time. | Mark observation unavailable/missed; never reconstruct earlier totals. |

Report a missed publication as soon as detected in an active session, with content ID, last verified state, cause, next action, owner and revised deadline. No silent rollover. If account access is absent, the manager still completes the ready buffer and presents the exact account-connection dependency; completed assets do not count as successful publication.

These are operating deadlines, **not a running service**. Sessions act when invoked. Continuous execution can be claimed only after a real trigger, credentials, always-on host, publication log, idempotency and failure reporting have been configured and verified. The [30 September audit](execution-2026-09-30/operations.md) found an inactive local legacy workflow and no connected credentials. This document does not activate it.

## Publication and performance truth

Maintain one ledger row per platform edition with: content ID, platform/account, stance intake, asset revision/hash, internal approval owner/time, applicable external-action authorization reference, proposed time/timezone, platform schedule ID if actually returned, actual publication time, platform post ID, permalink, status, failure reason and next owner/action. Asset, caption or claim changes invalidate approval for that revision.

States: Draft → In production → Ready for editorial review → Internally approved → Scheduled (platform/job receipt required) → Published (verified account evidence required). Failed and Unverified preserve failures rather than erase them. Manual publication can record a verified permalink/timestamp while leaving an unavailable API ID blank. Reconcile unknown outcomes before retrying the same content ID.
