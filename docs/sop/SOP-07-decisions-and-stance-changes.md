# SOP-07 — Decisions and stance changes

**Purpose:** Keep intellectual stance and closed-off options under founder control, and recorded.
**Owner:** Founder (acceptance). Codex integrates; only Codex sets task state ACCEPTED (`AGENTS.md`, collaboration protocol).

## Preconditions
Know the two records: `SHANIVAR_STANCE.md` (ST entries) and `docs/decisions/` (one file per decision that closes off an alternative; `docs/decisions/README.md:3-16`).

## Steps
1. **Rule:** a stance entry becomes ACCEPTED only when the founder explicitly accepts that exact entry/version and the evidence and date are recorded; no agent, test pass or popular source can provide that (`SHANIVAR_STANCE.md:5`). Today only ST-009 is ACCEPTED (2026-10-06); ST-001 to ST-008 are PROPOSED. The tagline is founder-given, not yet an entry (`tagline.md:5`).
2. New research goes in as PROPOSED, with the entry's fields (source, tradition, what sources say, disagreement, interpretation, product/practice implication, claim limits, founder decision, date).
3. A decision file `NNNN-title.md` uses the template: Context, Options (with rejected reasons), Decision, Consequences (honest costs), Revisit when (`decisions/README.md:20-41`). Number in order, never renumber; reversed decisions keep their file with `Status: Superseded by NNNN`.
4. Propose to the founder in plain words with the exact wording; wait for explicit acceptance; then record date and the founder's words.
5. Update affected docs (blueprint, calculations) in the same change; fix conflicts, don't hide them.

## Approval gates
Founder: every stance acceptance, every decision of status Accepted, any change to ST-009 wording (kept verbatim).

## Rollback
Never delete. Mark Superseded/Reversed and add the new record.
